零 · 主目标调整与全部意见处置

0.1 决策记录 D-0（用户确认，本版生效）

主验收目标（修订后）：在声明支持的模型集合上，以各模型的实际任务产出为主验收，通过逐模型优化达到可验证的最佳效果；提示词文本质量仅作辅助指标。
「最佳」的可验证定义：固定模型版本、固定任务集、固定运行环境、固定预算四要素下的统计验收结果（预注册主指标 + 区间估计）。不承诺对未来模型、未测任务或不同环境绝对最优。
与铁律一的关系：本决策不是新增原则，而是铁律一（提示词没有普适最优，只有针对特定模型的最优解）在验收层的落地——此前「任务层配对比较」的口径反而是铁律一的执行残留。

#复审意见级别处置与落点

P0-7签名自引用歧义、无时间容差与重放窗口；回调 SSRF；身份路由；台账内容与删除策略冲突修复§2.7：签名计算显式排除 signature 字段 + key_id + ±5min 容差 + 轮换双密钥；SSRF 防护套件（内网段拦截、DNS 一次解析、禁重定向、出口隔离）；tenant/connector 以认证主体为唯一可信来源；台账数据最小化（默认只存内容哈希与引用，全文存储须 opt-in 且受 TTL 与删除传播约束）。

P1-3Patch 意图自我声明可规避门禁采纳§4：服务端意图校验——按实际 diff 独立计算意图签名，与声明不符即 E_INTENT_MISMATCH 拒绝或强制重分类。
P1-4T1 缓存键缺解码/容器/驱动等分量采纳由 §2.1 的 EvalCacheKey 统一吸收（渲染键与评测键分离后各自完备）。
P2-1渲染缓存与推理缓存分离；墓碑归档；新 Agent 与新协议表述；灰度接入落地§2.1 双键分离；墓碑 180 天转冷存（ID 仍永不复用）；连接器表述改为「现有绑定下新 Agent = 配置；新协议 = 新适配器」；接入流程 v2 改四段灰度（§5）。

一 / Acceptance v2

评测体系 v2：五处结构修改

1.1 评测单元改为「任务 × 模型版本 × 提示词版本」

EvalUnit = {
  task_id,                 # 金标任务
  model_snapshot,           # 模型版本/指纹（T1 自托管为权重+环境七分量）
  prompt_variant           # ir_id + overlay 序列 + 渲染配置的 checksum
}
unit_id = sha256(task_id + model_snapshot + prompt_variant)

三条硬口径随之生效：① 所有统计检验在 unit 层配对——同一任务、同一模型下比较不同提示词版本；② 禁止跨模型混合计算总分，跨模型平均收益只作运营辅助指标，永不作门禁；③ 变量控制到 decode 参数与预算（同一 unit 内所有条件共享）。

1.2 逐模型独立优化：共享 IR + 模型 Overlay

「一份 IR 全模型共用」不再等于「一份提示词全模型共用」。数据模型增加 model_scope 维度：

Patch.model_scope ∈ { null, "glm5", "deepseek-v", "qwen-oss", ... }
# null = 基线补丁（作用所有模型）
# 具体模型 = Overlay 补丁（只作用于该模型）

渲染管线：IR(基线) ⊕ patches(scope=null) ⊕ patches(scope=model_id, 按版本序)
        → 模型卡渲染 → 该模型的 RenderedPrompt（携带 overlay_hash）
  • 基线 IR 承载意图（目标/材料/约束/验收），保持跨模型一致——这是可比性的来源；
  • Overlay 承载模型差异（结构偏好、指令位置、格式惯例、怪癖规避），由模型卡规则 + 模型专属 Patch 共同生成；
  • 冠军按模型分别产生：每模型的候选、评测、晋升、版本线互相独立；连接器暴露的 EvalEvidence 必须逐模型携带（见 §3 缓存隔离）。

1.3 逐模型基线与盲评协议 v2

要素v2 规则
B1 人工基线 × 模型作者每任务盲写一份模型无关的意图完整版，再做逐模型轻量适配（各 ≤5 分钟：结构/格式按模型惯例调整）；三模型合计估 12–18 人时。适配只改表面形式，不改语义——作者隔离与盲写规则不变。
B2 单策略基线 × 模型同样逐模型渲染（同一基线策略），探索性口径。
对照条件对齐同一模型版本、同一材料、同一 decode、同一预算——模型能力差异被完全控制，差异只能归因提示词。这是「避免把模型差异误认为提示词收益」的机械保证。
盲评对象3 名评审评审匿名化、随机排序的任务最终产出（候选、B1、B2 的输出混排，无来源标记）；rubric 与 done_criteria 来自基线 IR（逐模型共用验收标准，输出按模型分组评）。
文本评分的保留用途降为辅助指标：可解释性分析、冗余检查、失败诊断。一切对外「效果」声明只能引用任务产出结果；文本分不得出现在效果主张中。
B1 降级口径B1 无法落实 → 该模型门禁自动降为「兼容级候选」，对外声明强制标注「基线为单策略自动生成」，且不得使用与 B1 模型相同的产品价值结论。

1.4 三档门禁标签与全局安全闸

标签判定（逐模型独立）允许的声明
优化支持该模型自身预注册改善阈值达成（任务产出主指标，配对 Wilcoxon，中位配对差 ≥ δ_imp）＋ 回归集非劣（TOST）＋ 硬门全过「在该模型（版本/指纹）上经统计验证优于人工基线」
兼容仅非劣达标（TOST）＋ 硬门全过「在该模型上可用且不劣于基线」——禁止宣称效果最佳
不通过非劣未达或硬门失败不得列入受支持模型清单
  • 全局安全闸：任一必需模型出现安全违规、硬格式破坏或关键任务回归 → 整体不通过，逐模型成绩不抵扣（一个模型的优秀不能掩盖另一个模型的退化）。
  • 跨模型平均收益：仅运营视图（成本/覆盖趋势），永不进入门禁与晋升判定。
  • 连接器联动：/v1/model-cards 逐模型携带当前标签（优化支持/兼容）与达成时间、证据指针——外部 Agent 看到的支持等级与内部门禁严格一致。

1.5 功效分析与预算影响（诚实成本）

  • 样本量由功效分析产出：预注册须含 MDE、目标功效（0.8）、α（0.05）与基于校准集方差的计算记录；n=20 成为初始默认而非常量——功效不足时预注册二选一：增样本，或降低主张强度。确证集大小在预注册后锁定。
  • 逐模型成本结构：必需模型（主生产+备选）跑全量确证；低成本模型 P0a 从「兼容级」起步（L1/L2 + 回归非劣），预算允许再升优化支持级。
  • 人工预算上调：金标任务与标签（模型无关，一次建设）＋ B1 三模型 12–18 人时 ＋ 产出盲评（主模型全量 + 备选确证子集）≈ 45–75 人时（原 30–53 上调，原因：逐模型基线与逐模型盲评）。降级选项：备选改确证子集、低成本仅兼容级（约 30–45 人时，如实标注功效限制）。

二 / Contract Fixes

契约修复包：七项缺口的设计级关闭

2.1 引用锚定与双缓存键（P0-1）

# 规范引用锚定：弃用「版本相对章节号」，改用文档 ID + 条款 ID
SPEC-IR     IR/Patch 契约      SPEC-EVAL   评测与基准
SPEC-SEC    安全与租户治理      SPEC-CONN   连接器（v1.0-rc）
引用示例：SPEC-CONN#session-semantics 代替「v0.4 §5.1」（漂移源）

# 双缓存键（渲染与评测彻底分离）
RenderCacheKey = ir_checksum + overlay_hash + model_id + renderer_version
                 + template_version + decode          # 渲染=纯函数：可跨运行环境复用
EvalCacheKey   = RenderCacheKey + model_snapshot/指纹 + 环境七分量(T1)
                 + bench_version + baseline_id + repeats # 评测：禁跨环境/跨模型复用

连接器规范中「六元组缓存键」表述统一归入 RenderCacheKey；评测缓存按 EvalCacheKey 独立失效。TCK 增加用例：改 model_snapshot 或任一环境分量必须未命中（跨模型缓存复用 = 强制失效）。

2.2 Port 方向与状态去耦（P0-2）

  • 入站 Port（Generate/Iterate/Score/Render/Event/Discovery/Governance）：由核心应用服务实现，HTTP/MCP 适配器作为调用方。
  • 出站 Port（事件投递、回调、存储）：核心只依赖接口，由外围适配器实现（依赖倒置的另一半）。
  • TaskState 去耦：API 只承诺状态枚举（queued/extracting/rubric_pending/generating/evaluating/compiling/succeeded/failed/cancelled + result_class）与版本化迁移表；「枚举↔内部模块」的映射降为实现细节，内部重构不构成接口变更——修复连接器 v1.0 中「映射核心模块」与「外部不感知内部结构」的自相矛盾。

2.4 幂等、并发与原子性（P0-4）

  1. 职责分离：request_id 仅用于追踪，不参与去重；去重唯一由 (tenant_id, connector_id, op, idempotency_key) 数据库唯一约束承担。
  2. 载荷哈希绑定：首请求记录 sha256(canonical_request)；同键不同载荷 → 409 E_IDEM_PAYLOAD_MISMATCH。
  3. 重放语义精确化：重放返回首次结果及其原状态码（同步操作原样返回；异步任务返回当前任务状态）；E_IDEM_REPLAY 移入响应元数据字段，不再是「错误」。首次仍在执行中 → 返回 200 + in_progress 任务状态视图。
  4. 提交时原子 CAS：模拟通过后，提交在单数据库事务内执行「WHERE checksum = base 的条件更新」——模拟期间被并发修改 → 条件更新零行命中 → 返回 E_BASE_DRIFT，无覆盖、无脏写。
  5. 台账原子性：新 IR 提交、幂等记录、审计追加在同一事务（审计写入失败则整体回滚——审计是提交的组成部分，不是事后日志）。
  6. 键生命周期：默认保留 72h（可配），TTL 清理；重放窗口与保留期一致，过期后同键视为新请求（显式记录该行为，杜绝「过期后重放静默重复执行」）。

2.5 授权与建议的内容绑定（P0-5）

ProtectionAuthorization = {
  tenant_id, ir_id, base_checksum,        # 归属与基线
  patch_hash,                              # ★ 精确补丁内容哈希（JCS）
  loc, op_type, expires_at,
  single_use: true, consumed_at            # ★ 单次消费，重放 → E_PROTECT_CONSUMED (409)
}
# 载荷递归校验：服务端管理字段清单 {protect_class, provenance, created, meta}
# 任何 ADD/REWRITE 的替换载荷（含嵌套对象）出现清单字段 → E_PROTECT_FIELD
# 仅校验 loc 字符串不再足够——整棵载荷树都是校验对象

# 建议应用：调用方不再携带 op 序列
POST /v1/sessions/{id}/patches { suggestion_id, 四元组确认 }
→ 服务端按 id 取出不可变建议 Patch，核对 patch_hash 与四元组 → 走应用器
→ 修改过的建议既取不到（id 不存在）也换不进来（hash 不匹配）

2.6 时间模型与事件语义（P0-6）

问题定稿
双时钟模型执行超时（单次调用 120s；任务累计计算预算独立配置）与人工确认有效期（rubric 确认 72h、保护审批 7 天）分离。任务 15 分钟上限仅适用于计算阶段
重评分异步接管score.v1：L1 与小规模 L2 保证 10s 同步；超限（多候选/任何 L3）→ 202 + task_id，走异步任务模型；同步端点永不挂死。
降级结果语义result_class ∈ {full, degraded, partial} + degraded_reason：超时/预算耗尽返回已完成层级的部分结果时必须显式标注，禁止与完整结果同形态交付。
统一状态事件task.state_changed（含状态快照）为规范事件，task.completed/failed 为兼容别名；新增 rubric.confirmation_required、task.cancelled；取消与完成的竞态规则：完成事务先提交则取消返回 409（终态不可逆）。
会话语义session_epoch 递增于：补丁应用、人工编辑、任务切换；会话显式关闭或空闲 24h 自动过期；事件携带单调 turn_seq，乱序 → E_EVENT_ORDER 拒绝由客户端重试。

2.7 回调安全与数据最小化（P0-7）

  • 签名规范化：HMAC 计算输入 = 事件的 canonical JSON 去除 signature 字段（显式排除，消除自引用歧义）+ key_id + 时间戳 ±5min 容差 + event_id 去重窗口 72h；轮换期双密钥并验（旧钥宽限 24h）。
  • SSRF 防护套件：注册与每次投递双重校验 URL——拒绝内网/保留段/环回/链路本地/云元数据端点；DNS 解析一次并直连结果 IP（防重绑定）；禁自动重定向；出站统一经隔离代理；租户可收紧为白名单模式。
  • 身份以认证主体为准：tenant_id/connector_id 由 token/mTLS 主体反查获得；正文值仅做一致性核对，不符 → 401 E_AUTH_IDENTITY_MISMATCH，绝不参与授权路由。
  • 台账数据最小化：哈希链默认只存元数据与内容哈希（谁、何时、改了哪个 loc、patch_hash）；提示词全文、对话与材料仅在租户 opt-in 保留策略（TTL + 删除传播 + PII 扫描）下以引用方式存储，WORM 约束只施加于哈希与元数据——消除「不可篡改」与「可删除」的冲突。

四 / Intent Check

意图服务端校验与 TCK 增补

复审指出：Patch 意图由创建方自我声明，可选宽松意图规避门禁。修复——意图不采信声明，采信 diff：

  1. 意图签名：应用器在模拟阶段依据实际 op 序列计算意图签名（如：仅含 DELETE/MOVE + token 下降 → simplify；含 ADD 约束/REWRITE goal → improve；修复类绑定失败签名引用 → fix）。
  2. 一致性判定：签名与声明不符 → E_INTENT_MISMATCH(422) 拒绝，或返回建议意图供创建方确认后重提交。
  3. 门禁按校验后的意图执行：v0.4 §5 的四类判据不变，但作用对象是校验后的意图——声明宽松、diff 实严的补丁按实际意图受门。

五 / Onboarding v2

接入流程 v2：四段灰度取代二值切换

  1. 沙箱 TCK：沙箱租户 + Mock 绑定，全能力契约测试通过（不变）。
  2. 最小权限生产灰度：sandbox:false 但 scopes 仅开放 discovery + 单一能力（通常 generate.v1），配额 ≤ 5 任务/日，回调白名单模式。
  3. 指标观察：作废率、P95 时延、错误率、预算消耗在运营指标表（§6.2 口径）观察 ≥ 1 个观察窗；异常即回缩权限。
  4. 逐能力提升配额：每新增能力（iterate → events）重复 2–3 段；events.v1（在线模式）最后开放且永远最后开放——它的风险面最大。

回缩与吊销：任一观察窗内 TCK 类故障（并发、越权、篡改）复现 → 冻结该连接器新任务、只读模式排查；吊销即时生效并入审计链。回调运维：重试带抖动、死信队列与人工重放工具随 P1 交付。
