一 / S0-1 Closure

loc 与 checksum 契约：设计定稿

1.1 loc 正式文法（v1）

# loc 文法 v1 —— 补丁与缓存寻址的唯一合法形式
loc        := root "." segment ( "." segment )*
root       := "slots" | "freeform_extras"        # meta/protect_registry 不可经普通 Patch 修改
segment    := field | list_select
field      := identifier                          # 例：slots.goal.outcome
list_select := field "[" item_id "]"               # 例：slots.constraints.must[c-must-001]
                                                            #  ↑ 方括号内是稳定 ID，不是数组下标
item_id    := [a-z0-9-]{6,16}                     # 分配规则见 1.2

# 违法示例（应用器必须拒绝，错误码见 1.4）
# slots.constraints.must[0]      → 下标寻址（E_INDEX_FORBIDDEN）
# slots.meta.version             → 越权根（E_ROOT_FORBIDDEN）
# freeform_extras[F-3].text      → 允许：自由项字段可 REWRITE，但不可经 loc 增删子字段

复审指出「must[0] 在删除、插入、MOVE 后会漂移」——定稿裁决是彻底废除下标寻址：持久化 loc 中只允许稳定 ID。数组顺序只影响渲染顺序，不影响寻址；重排走 MOVE，永不改键。由此删除、插入、MOVE 三类操作之后，历史 loc 全部保持可解析（或命中墓碑，见 1.2）。

1.2 稳定 ID 分配与墓碑机制

  • 分配即确定：列表项创建时分配 item_id，由 hash(patch_id, op_index) 或 hash(ir_id, creation_seq) 确定性派生（非时间戳类 ULID）。重放同一 Patch 必得同一 ID——这是「确定性重放」能成立的前提。
  • ID 永不复用：DELETE 不物理移除，写入台账墓碑（tombstone：item_id、删除补丁、时间、证据引用）。墓碑永久保留。
  • 命中墓碑的 loc：应用器返回 E_LOC_RETIRED，整包拒绝——比静默 CAS 失败给出更精确的错误归因，同时天然阻止 ID 复用攻击。
  • 同 loc 单补丁单操作：一个 Patch 内禁止两条 op 指向同一 loc（需多步改同一路径时拆成多个 Patch，形成链）。

1.3 Canonical JSON 与 checksum 计算式

序列化标准：RFC 8785（JCS）——键排序、无冗余空白、UTF-8、
             数值按 ECMAScript JSON.stringify 规范化
checksum    = SHA-256( JCS( IR \ { checksum } ) )   # 唯一排除字段：checksum 自身
                                                              # version / created / 全部 slots 均参与计算
实现要求：  任何语言实现必须通过同一组官方测试向量
             （规范交付物的一部分，含中文键名、空数组、0.1 类浮点等边界样本）

选择 RFC 8785 而非自定规则的理由：它把「键序、空白、数值规范化」三件最容易实现走样的事全部钉死，且有现成测试向量可引用——复审担心的「相同 IR 产生不同 checksum」由测试向量闭合。

1.4 Patch 操作顺序与原子性语义

  1. 按序执行：ops 严格按数组顺序执行；第 N 条 op 针对「前 N−1 条已应用后的状态」校验与应用。应用器不得重排。
  2. 全有或全无：任何一条 op 失败（含前置 CAS、loc 解析、保护类冲突），整包拒绝，副本丢弃，零部分应用。
  3. 先验后用：应用前依次校验 base.checksum（CAS）→ 全部 loc 可解析且无墓碑 → 保护类约束（enacted 项不可 DELETE）→ 同 loc 唯一性。四关全过才开始变更。
  4. 纯函数：应用器 = (base_IR, Patch) → new_IR 的纯函数，不读时钟、不读随机源、不打外部服务；所有时间戳取自 Patch 头部而非应用时刻。
错误码触发
E_BASE_DRIFTbase.checksum 与当前不符（基线已被其他补丁更新）
E_INDEX_FORBIDDENloc 含数组下标
E_ROOT_FORBIDDENloc 越权进入 meta / protect_registry
E_LOC_RETIREDloc 命中墓碑
E_PROTECT_ENACTEDDELETE 目标为 enacted 保护项
E_LOC_CONFLICT同 Patch 内多条 op 指向同一 loc
E_IDEM_REPLAY幂等键命中（非错误：返回首次结果，不重复应用）

二 / S0-2 Closure

统计验收口径：设计定稿

废除一条，补上五条。废除：「两组 CI 重叠即记无显著差异」（复审正确指出这在配对设计下不成立）。补上：样本单位、配对检验、多重比较控制、评审一致率、预注册时序。以下五项合起来构成评测规范的统计骨架，规范只做转写。

2.1 校准 / 确证物理切分：把「预注册」从口号变成时序约束

  1. 基准构建：30 个金标任务固定切分为校准集 10 + 确证集 20，切分一经确定不可调整（防止「看完结果再定区间」）。
  2. 校准阶段：系统只允许接触校准集；在它上面调 rubric、定验收阈值、跑通流程。
  3. 预注册：主指标、检验方法、显著性水平（α=0.05）、通过阈值、Holm 校正范围，全部写入带时间戳的分析计划并冻结。此后任何修改都构成新的实验（须重新跑确证集）。
  4. 确证一次：系统在确证集上单次运行，报告效应量 + 区间 + p 值。确证集不参与任何调参回路——它是「只考一次的考场」。

样本单位 = 任务。重复 3 次用于压低任务内方差后取任务均值；分析在任务层面进行。评审 3 人评分先报告一致率（见 2.2），再聚合。任何「按重复次数凑样本量」的做法都被此定义排除。

2.2 检验方法与评审规则

问题定稿规则
候选间比较（连续/等级分）配对 Wilcoxon 符号秩检验，作用于同一任务上的成对差值；同时报告配对差值的中位数与 bootstrap 95% 区间
硬门通过率（二元）McNemar 配对检验（同任务对同候选的通过/未通过配对）
多重比较预注册唯一主比较（冠军 vs 基线）；其余比较全部标记为探索性，若需同时下结论按 Holm 逐步校正
「无差异」结论的语言纪律只能说「在 α 下未检出差异」；要宣称「等效」必须用预注册边界的 TOST 等效检验——两者禁止混用
评审一致率Krippendorff α（等级数据）；α < 0.67 → 中止评测、先校准 rubric；争议任务由 2/3 多数裁决并留痕，争议率进报告
小样本声明确证集 n=20 检验功效有限，P0a 结论定位为「门槛判定」，不得外推为「系统有效性证明」（沿用 v0.2 的冒烟定位并写死）

三 / S0-3 Closure

protect_registry 权限模型：两态三权一周期

复审的担忧成立：如果生成器能把任意约束自我标记为 safety，保护机制就变成纠错免疫。定稿模型：

要素规则
两态proposed（建议保护，由生成器/消融/校验器均可创建）→ enacted（已批准保护，删除豁免仅对 enacted 生效）。proposed 项走正常消融-删除流程，只是复核优先级提高。
三权提议权：系统组件皆可；批准权：仅用户或管理员角色（生成器、消融器、裁判一律无批准权，无例外）；解除权：批准人本人或管理员，解除必须写理由并留痕。
一周期enacted 项带 review_by（默认 90 天）。到期进入「复核到期」态：保护继续生效但审计告警，超期未复核计入治理报告。
防滥用登记必须附理由与证据引用；审计抽检增加「保护滥用率」指标（被 enact 后从未复核、且消融显示零增益的项占比），超阈值触发全量保护项复核。
与 §1 的接口protect_registry 不在普通 loc 根内（E_ROOT_FORBIDDEN）；其变更走独立的 ProtectionChange 记录，与 Patch 流水分离。

四 / S0-4 Closure

复现层级：把「可精确复现」换成三级诚实声明

复审指出多数供应商只给别名、不给严格快照——v0.2 的「任何一次评测可精确复现」超出能力，撤回。替换为三级体系，每级绑定捕获清单、允许的声明、失效策略：

层级适用条件允许的声明失效策略
T1 钉死 自托管 / 权重快照可固定 「可复现」——重放结果逐字节一致 缓存长期有效；仅随渲染器/模板版本升级失效
T2 别名+指纹 供应商给出版本别名，可取指纹 「条件复现：供应商版本未变时」 周期漂移巡检（每周 3 任务探针集重跑）；指纹变化 → 该模型全部缓存 EvalRun 与相关结论级联失效并标记
T3 仅别名 只有模型名，无版本信息 「最佳努力复现，结论具时效性」 结论 14 天有效期；任何晋升/门禁决策前必须重验；探针集同 T2

捕获清单（EvalRun 必填，缓存键的组成部分）：模型别名与可获得的最细版本标识、探针响应指纹（对 N 条标准化探针请求的响应哈希）、完整解码参数（temperature、top_p、top_k、stop、seed、max_tokens、惩罚项）、renderer_version、template_version、基准集版本、供应商请求/响应 ID。缓存键在 v0.2 四元组基础上扩为：ir_checksum + 模型标识 + 指纹 + renderer_version + template_version + decode。

声明门禁联动：§0.2 冻结的「评测可复现」声明，解冻后的合法形式是——只有 T1 结论可称「可复现」，T2/T3 按上表口径。对外报告一律附层级标签，供应商静默升级造成的漂移由巡检兜底而非口头承诺兜底。

五 / P1 Package

P1 四项：意图新鲜度、在线参数、信任边界、预算

5.1 意图新鲜度：四元组校验取代二元校验

复审找到的洞是真实的：用户口头纠正目标、补充材料、改完成标准，但 IR 尚未重生成时，旧补丁仍能通过 checksum 校验。定稿方案——在途补丁携带四元组，应用前逐一核对：

inflight_patch.carries = {
  session_epoch,      # 会话代次（任务切换/手动编辑/补丁应用 → +1）
  base_checksum,      # IR 基线 CAS
  intent_hash,        # hash(意图框架最新版)：目标/完成标准/约束的语义摘要
  context_hash        # hash(最近 3 轮对话 + 输入材料内容哈希)
}
# 任一新对话轮到达 → context_hash 变化 → 该任务名下全部在途补丁作废
# 作废 ≠ 重放：基于新上下文重新触发生成，旧补丁仅留作负样本

输入材料（上传文件、引用）单独维护内容哈希作为 input_version；文件被替换即使同名也触发失效。

六 / S2 Decisions

四项延后事项：三项本版裁定，一项保留触发式

事项裁定
组合消融成本 P2 落地，规则本版先定：仅对筛查得分 top-K（K=5）做组合消融，对数 ≤ K(K−1)/2 = 10；每对重复 3 次；单次消融会话设调用封顶（默认 60），超限即终止并输出「证据不足」而非硬跑。
DPO 训练目标 裁定唯一主目标 = Patch 序列预测：输入（对话上下文、意图框架、基线 IR、缺陷证据），输出（v2 契约的 op 序列）；辅助目标 = 种子→IR 结构化抽取（仅用于 SFT 冷启动）。整 IR 自由文本生成不作为训练目标，防止目标混杂。P2 数据卡按此格式锁定。
删除传播边界 「可撤销」仅覆盖：原始记录、策略卡、示例、缓存、未进入训练的数据批次。已训权重不承诺撤销——只能回滚 checkpoint、切影子版本或重训；强制维护 checkpoint↔数据批次血缘映射，投毒批次暴露时按映射定位需回滚的权重版本。v0.2 §9.2 相关表述按此收紧。
同族裁判校准 保留为触发式任务：仅当 D2 实测被迫同族时启动——建 50 对人工标定集、测量偏好方向与强度（长度偏好/同族偏好）、在裁决聚合中加校正项、季度复标一次；P2 质量门增加「标定报告」。
