Part 1 · 主目标与设计立场

一 / Goal & Principles

主目标与六条铁律

主验收目标（决策 D-0）：在声明支持的模型集合上，以各模型的实际任务产出为主验收，通过逐模型优化达到可验证的最佳效果；提示词文本质量仅作辅助指标。
「最佳」的可验证定义：固定模型版本、固定任务集、固定运行环境、固定预算四要素下的统计验收结果（预注册主指标 + 区间估计）；不承诺对未来模型、未测任务或不同环境绝对最优。
#铁律本方案的机械落地
一提示词没有普适最优，只有针对特定模型的最优逐模型 Overlay、逐模型冠军、三档标签、跨模型缓存禁用（§3.3 / §2.5）
二评估信号的上限就是优化效果的上限rubric 人工锚点 + 冻结基准 + 功效分析前置（§3.2 / §3.6）
三相对优于绝对，结构优于措辞成对裁决交换双裁；一切可结构化的约束进 IR 结构字段（§2.2）
四三种证据不可互换IR 静态分 / 文本 rubric 分 / 任务执行分各支持对应强度结论（§2.1）
五基准与版本记录先于一切自动化版本台账与冻结基准前移至 P0（§8.1）
六任务产出是主验收，文本只是辅助盲评对象 = 模型最终产出；文本分降为诊断指标（§3.4）——D-0 的规则化

Part 2 · 核心对象与契约

二 / Core Contracts

核心对象与契约

2.1 三对象证据链

对象承载能证明不能证明
PromptIR结构化意图（唯一事实源）结构合法、无自相矛盾、可渲染（规则检查，零调用）任何质量或效果结论
RenderedPrompt[]同一 IR 的逐模型投影（模型快照 + 渲染器 + 解码参数）表达质量的相对序（裁判 rubric）绝对可用性；执行效果
EvalRun[]目标模型上的执行记录（用例集版本 + 重复 + 指标 ± CI95）「适配该模型」的唯一证据；回归判定对未测模型/未来版本的承诺

结论强度随证据层级递增、不可跨级引用：渲染过静态检查 ≠ 适配；裁判偏好 ≠ 效果更好。对外一切「效果」声明只能引用 EvalRun（铁律六）。

2.2 IR v3：单一事实源 + 模型 Overlay

IR = {
  schema_version: "3", ir_id, version, parent_ir_version, lineage_id, checksum,
  slots: {                                  // ★ 唯一事实源（指令清单 = 编译期派生物）
    role, goal { outcome, done_criteria[], non_goals[] },
    inputs [ { ref, type, note, trust } ],
    output { format, schema?, length_budget },
    constraints { must[], must_not[], style[] },
    examples [ { input, expected } ],
    workflow [ "…" ],
    feedback_protocol { on_fail_report: "现象|复现|已尝试|影响面" }
  },
  freeform_extras: [ { id, text, note?, provenance } ],   // 少数无法结构化的表达
  provenance_map: { "": { source: "user_turn:3 | seed | derived:r7 | gen:s2" } },
  protect_registry: [ { loc, class, state, by, at, review_by } ]
}
Patch = {                                   // 编辑单元（v2 契约 + v0.5 扩展）
  schema_version, base { ir_id, version, checksum }, idempotency_key,
  model_scope: null | "glm5" | "deepseek-v" | … ,   // ★ null=基线补丁；具体值=模型 Overlay
  intent: "improve|simplify|fix|protect",           // 声明意图（服务端按 diff 校验，§3.7）
  ops [ { op: ADD|DELETE|REWRITE|MOVE, loc, content?, reason, evidence_refs[] } ],
  transaction: "all_or_nothing"
}
# 渲染管线：IR ⊕ patches(scope=null) ⊕ patches(scope=model_id, 按版本序) → 模型卡渲染
  • lineage_id：同一谱系永不跨训练/测试集（自学习数据治理，§4.3）。
  • model_scope：基线 IR 保证跨模型可比性，Overlay 承载模型差异——「一份意图、N 份提示词」。
  • checksum = SHA-256(RFC 8785 JCS(IR\{checksum}))，跨实现以官方测试向量闭合。

2.3 loc 文法 v1.1 与两阶段执行模型

loc         := object_loc | array_loc
object_loc  := "slots" "." segment ("." segment)*
array_loc   := "freeform_extras" "[" item_id "]" ("." ff_field)*
segment     := field | list_select
list_select := field "[" item_id "]"            # 方括号内是稳定 ID，数组下标寻址被废除
field       := [a-z][a-z0-9_]*   ff_field := "text"|"note"|"provenance"
item_id     := [a-z0-9][a-z0-9-]{4,14}[a-z0-9]  # 6–16 位、全小写、首尾非连字符、永不复用
# 合法：slots.goal.outcome ｜ slots.constraints.must[c-must-001] ｜ freeform_extras[f-a1b2c3].text
# 非法：…must[0]→E_INDEX_FORBIDDEN ｜ slots.meta.version→E_ROOT_FORBIDDEN ｜ …[F-3]→E_ID_SYNTAX

op-loc 兼容矩阵（16 格全裁决）：ADD→仅列表容器（追加，ID = hash(patch_id, op_index) 确定性派生）；DELETE→仅列表项或空容器（非空 → E_DELETE_NONEMPTY，写墓碑）；REWRITE→标量路径 / 列表项 / ff 子字段；MOVE→仅列表项重排（对抗中段遗忘）。

核心错误码（应用器）触发
E_BASE_DRIFT前置 CAS 不符，或提交时条件更新零行命中（并发竞态）
E_INDEX_FORBIDDEN / E_ROOT_FORBIDDEN / E_ID_SYNTAX / E_FIELD_UNKNOWNloc 词法与越权（含墓碑 E_LOC_RETIRED）
E_ADD_TARGET / E_DELETE_TARGET / E_REWRITE_TARGET / E_MOVE_TARGET / E_DELETE_NONEMPTYop-loc 兼容矩阵禁止的组合
E_PROTECT_ENACTED / REWRITE / MOVE / ANCESTOR / FIELDenacted 只读、祖先保护、服务端管理字段（§2.4）
E_PROTECT_CONSUMED授权单次消费后重放
E_INTENT_MISMATCH声明意图与实际 diff 不符（§3.7）
E_IDEM_REPLAY幂等命中（响应元数据，非错误，返回首次结果）

2.4 保护类 v1.1：两态三权一周期 + 内容绑定

  • 两态：proposed（系统组件可建）→ enacted（仅用户/管理员批准；生成器、消融器、裁判、连接器一律无批准权）。删除豁免不对 proposed 生效。
  • 只读化：enacted loc 对普通 Patch 的 DELETE / REWRITE / MOVE 全拒；改父对象间接改写 → E_PROTECT_ANCESTOR。
  • 载荷递归校验：服务端管理字段清单 {protect_class, provenance, created, meta} 出现在任何替换载荷的任意深度 → E_PROTECT_FIELD——只查 loc 字符串不够，整棵载荷树都是校验对象。
  • 授权通道：确需修改 → ProtectionChange 批准后生成授权，绑定 {tenant_id, ir_id, base_checksum, patch_hash, loc, op_type, expires_at, single_use}——精确内容哈希 + 单次消费，重放或换内容均被拒。
  • 一周期：enacted 带 90 天复核期；「保护滥用率」（enact 后从未复核且消融零增益的占比）入审计抽检。

2.5 复现层级与双缓存键

RenderCacheKey = ir_checksum + overlay_hash + model_id + renderer_version
                 + template_version + decode            # 渲染=纯函数，可跨运行环境复用
EvalCacheKey   = RenderCacheKey + model_snapshot/指纹 + 环境七分量(T1)
                 + bench_version + baseline_id + repeats   # 评测：禁跨环境/跨模型复用
层级条件允许的声明失效策略
T1 受控环境七分量全钉死：权重快照、推理框架、硬件、并行/batch、浮点确定性、tokenizer、拼接模板「在所记录环境内重放逐字节一致」任一分量不可固定 → 自动降 T2，禁手动标 T1
T2 别名+指纹供应商别名 + 探针指纹 + 请求 ID「条件复现：供应商版本未变时」每周探针巡检；指纹变化 → 缓存与结论级联失效
T3 仅别名仅模型名「最佳努力复现，结论 14 天时效」任何晋升决策前必须重验
Part 3 · 评测体系 v2

三 / Acceptance v2

评测体系 v2：逐模型、以任务产出为主

3.1 评测单元：任务 × 模型版本 × 提示词版本

EvalUnit = { task_id, model_snapshot, prompt_variant(=ir + overlay + 渲染配置的 checksum) }
unit_id = sha256(task_id + model_snapshot + prompt_variant)
# 三条硬口径：① 检验在 unit 层配对（同任务同模型下比不同提示词）
#           ② 禁跨模型混合计分，跨模型平均仅运营视图
#           ③ 同 unit 内所有条件共享 decode 与预算（模型能力差异被控制）

3.2 统计骨架：校准 → 预注册 → 确证一次

  1. 基准构建：30 金标 = 校准 10 + 确证 20 物理切分（功效分析可调样本量，预注册后锁定）；另建隐藏集 ≥10 任务从不参与调参与晋升。
  2. 校准：只接触校准集，调 rubric、定阈值。
  3. 预注册：主指标、检验、α=0.05、MDE 与功效计算、通过阈值、基线构建协议（B1 作者隔离与盲写、封存时间戳）全部带时间戳冻结；确证前不得修改。
  4. 确证一次：确证集单次运行，报告效应量 + 区间 + p。配对 Wilcoxon（连续）/ McNemar（硬门）/ TOST（等效）；唯一主比较 + Holm 校正；「未检出差异」≠「等效」。

评审规则：3 名评审、Krippendorff α ≥ 0.67（α 不足先校准 rubric）、争议 2/3 多数裁决留痕；三级评估信号（L1 规则 / L2 交换顺序成对裁决 / L3 目标模型执行）逐级淘汰、成本递增。

3.3 逐模型优化：共享 IR + Overlay + 逐模型冠军

多策略候选生成（骨架填充 / 范例锚定 / 自由撰写 / 极简约束四派并行，策略 ID 入元数据）、删除判定四级证据阶梯（筛查 → 重复≥3+组合消融 → 保护类豁免 → 人工降级）、no-op 判失败——三项机制按模型分别执行；策略学习按「任务类型 × 模型 × 意图」三桶归因。

3.4 逐模型基线与盲评协议 v2

要素规则
B1 人工基线 × 模型隔离作者每任务盲写一份模型无关的意图完整版，再做逐模型轻量适配（各 ≤5 分钟，只改表面形式不改语义）；三模型合计 12–18 人时
B2 单策略基线 × 模型骨架模板直出，逐模型渲染；探索性口径
盲评对象模型最终任务产出（候选/B1/B2 输出匿名混排、随机顺序、无来源标记）；rubric 来自基线 IR，输出按模型分组评
文本评分用途降为辅助：可解释性、冗余检查、失败诊断；一切「效果」声明只能引用任务产出结果
B1 降级口径B1 不可落实 → 该模型自动降「兼容级候选」；对外强制标注「基线为单策略自动生成」，不得沿用人工基线的价值结论

3.5 三档门禁与全局安全闸

标签判定（逐模型独立）允许的声明
优化支持自身预注册改善达标（配对 Wilcoxon，中位配对差 ≥ δ_imp）+ 回归集非劣（TOST ε_ni）+ 硬门全过「在该模型（版本/指纹）上经统计验证优于人工基线」
兼容仅非劣达标 + 硬门全过「可用且不劣于基线」——禁止宣称效果最佳
不通过非劣未达或硬门失败不得列入受支持清单

全局安全闸：任一必需模型出现安全违规、硬格式破坏或关键任务回归 → 整体不通过，逐模型成绩不抵扣。跨模型平均收益仅运营视图。/v1/model-cards 逐模型对外披露当前标签与证据指针，内外口径严格一致。

3.6 功效分析与预算（诚实成本）

  • 样本量由功效分析产出（MDE、功效 0.8、α 0.05，基于校准集方差）；n=20 是初始默认而非常量，功效不足时预注册「增样本」或「降主张」二选一。
  • 必需模型（主生产+备选）跑全量确证；低成本模型从兼容级起步，预算允许再升。
  • 人工预算：45–75 人时（金标一次建设 + B1 三模型 12–18 + 产出盲评主模型全量/备选确证子集 + 培训与争议裁决）；降级档 30–45（备选改确证子集、低成本仅兼容，如实标注功效限制）。预算未冻结不进确证。

3.7 意图服务端校验

意图不采信声明、采信 diff：应用器在模拟阶段依据实际 op 序列计算意图签名（仅 DELETE/MOVE + token 下降 → simplify；新增约束/改写目标 → improve；绑定失败签名引用 → fix），与声明不符 → E_INTENT_MISMATCH 拒绝或强制重分类。门禁按校验后意图执行——声明宽松、diff 实严的补丁按实际意图受门；no-op（模拟前后 checksum 相同且无墓碑变化）判失败，不计入成功样本与学习正例。

Part 4 · 在线模式与自学习

四 / Online & Learning

会话内改进与自学习闭环

4.1 语义门控与四元组校验

在途补丁携带四元组 {session_epoch, base_checksum, intent_hash, context_hash}；新对话轮先分类——寒暄/确认/进展汇报不作废（仅刷新对话窗口），材料/目标/约束/纠正进入 30s 去抖窗口后按最新状态重排，不确定保守作废。context_hash 只由语义类轮 + 材料内容哈希参与计算。饿腹防护：作废率 = 作废/生成 > 60%（滑动 50 任务）告警回顾分类规则。

参数（v1 定值）定义
归因窗口 k / 失败判定 mk=3 个可评估轮；窗口内连续 2 次同一失败签名才判无效回滚（滞回：间有一次成功即清零）
失败签名(失败类, loc 提示桶, 现象聚类 ID) 三元组完全一致
应用策略默认人工确认；自动应用为未来研究项（门槛：连续两次独立 EvalRun 正向 + rubric 无冲突）
两率分报建议采纳率 = 确认应用/建议；采纳后改善率 = 窗口内 EvalRun 改善或用户确认/已应用；零建议期报 N/A 不报 0

可观测性八指标（定义/分母/窗口与告警线入运营规范）：建议产出率、作废率、人工采纳率、采纳后改善率、误伤率、误回滚数（>0 即事件级告警）、P95 时延、单任务成本。

L2 元进化生成器元提示词新版本M4 的「大脑」（冠军/挑战者）冻结基准 + 回归集双重胜出
L3 权重蒸馏SFT/DPO checkpoint小型 Patch 改写器仅三条件齐：P4 稳定且遇明确瓶颈 + 独立测试非劣（预注册 ε）+ ROI 完整评估
  • 训练目标裁定：主目标 = Patch 序列预测（输入：上下文+意图框架+基线 IR+缺陷证据）；辅助 = 种子→IR 结构化抽取（仅 SFT）；整 IR 自由生成不作训练目标。
  • 弱监督治理：裁决日志 = 裁判弱标签；偏好对必须同上下文（同对话前缀+同模型+同渲染解码）；按 lineage 血缘切分防版本近邻泄漏；每批次人工抽检 ≥3% 报一致率。
  • 撤销边界：可撤销 = 原始记录、策略卡、示例、缓存、未训练数据集；已训权重不承诺撤销（回滚/影子/重训 + checkpoint↔数据批次血缘映射）。
  • 防退化护栏：自生成数据占比硬顶（≤30%）、冻结基准、嵌入多样性巡检、负样本保留、人工审核门（L2 晋升与 L3 上线必签）。

6.5 异步任务模型与双时钟

回调：at-least-once + 按 event_id 去重（窗口 72h）；HMAC 签名输入 = 事件 canonical JSON 去除 signature 字段 + key_id + 时间戳（±5min 容差），轮换期双密钥并验（旧钥宽限 24h）。轮询兜底：任务最长存活 15 分钟（计算时钟），超时自动 failed 并返回已完成层级部分结果 + degraded 标注。

6.6 幂等、错误模型与安全基线

规则定稿语义
唯一约束 + 载荷哈希(tenant, connector, op, idempotency_key) 唯一；首请求记录 sha256(canonical_request)；同键异载荷 → 409 E_IDEM_PAYLOAD_MISMATCH
重放语义返回首次结果及其原状态码；首次仍在执行 → 200 + in_progress 状态视图；E_IDEM_REPLAY 为响应元数据非错误
键生命周期保留 72h（可配），TTL 清理；过期后同键视为新请求（显式记录，杜绝静默重复执行）
传输层错误码E_AUTH401 / E_SCOPE403 / E_RATE_LIMIT、E_BUDGET_EXCEEDED429+Retry-After / E_AUTH_IDENTITY_MISMATCH401（正文身份与认证主体不符）/ E_EVENT_ORDER422（turn_seq 乱序）/ E_UNSUPPORTED_OP501；核心 E_* 全集透传含 @ op[N]
SSRF 防护套件注册与投递双重校验：拒内网/保留段/环回/链路本地/云元数据端点；DNS 解析一次直连结果 IP；禁自动重定向；出站经隔离代理；租户可收紧白名单模式
预算与降级连接器维度独立限额（任务/日、token/任务、L3 深度开关默认 off）；超限显式 429 而非静默排队；部分结果必须标注 degraded

6.7 在线事件模型：suggestion_id 不可变

  1. 开会话：POST /v1/sessions（绑定 ir_id）→ session_id, epoch=0。epoch 递增于：补丁应用、人工编辑、任务切换；显式关闭或空闲 24h 过期。
  2. 推轮次：events 推 turn.recorded（轮文本 + 材料 content_hash + 单调 turn_seq）；语义分类在系统侧（§4.1），host 无权覆盖。
  3. 建议回调：suggestion.proposed 推送 {suggestion_id, patch_hash, 四元组, 证据, 信号类别}。
  4. 确认应用：host 只提交 {suggestion_id, 四元组确认}——不携带 op 序列；服务端按 id 取出不可变建议 Patch，核对 patch_hash 与四元组后走应用器。改过的建议既取不到（id 不存在）也换不进来（hash 不匹配）。
  5. 效果归因：窗口、滞回判定全在系统侧；host 经 governance.read.v1 读结果——在线指标口径（两率分报、误回滚=0）不被外部实现稀释。
