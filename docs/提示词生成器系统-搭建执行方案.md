## 1. 系统定义与范围

**一句话定义**：面向文本/系统提示词的「生成—迭代—评测」系统：把用户意图解析为结构化 IR，经多策略生成、三级评估、逐模型渲染，产出各目标模型上的最优提示词；支持会话内动态改进与外部 Agent 连接器接入。

**主验收目标（D-0，不可更改）**：以**各目标模型的实际任务产出**为主验收；提示词文本质量仅为辅助指标。「最佳」= 固定模型版本 + 任务集 + 环境 + 预算下的统计验收结果。

**做什么**：从零生成 / 种子迭代 / 静态评分 / 渲染 / 在线会话改进 / 连接器开放（能力见 §10）。
**不做什么（禁止实现）**：
- 消息角色编排、工具 schema、多 Agent 编排、文生图提示词；
- 无状态网关模式（外部 Agent 不得自带 IR 绕过系统写者）；
- L3 权重蒸馏（法务评估前冻结，见 §14 D-14）；
- 服务端抓取任意外部 URL 材料（材料只能经 blob 上传，见 §7.3）。

## 4. 核心数据契约（IR / Patch / 错误码）

### 4.1 IR v3（Pydantic，`ir.py`）

```python
class Goal(BaseModel):
    outcome: str
    done_criteria: list[str] = []
    non_goals: list[str] = []

class SlotInputs(BaseModel):
    ref: str                 # blob_id，或 "inline:<text>"
    type: str                # text|json|image|pdf
    note: str = ""
    trust: Literal["user","derived"] = "user"

class IR(BaseModel):
    schema_version: Literal["3"] = "3"
    ir_id: str; version: int; parent_ir_version: int | None
    lineage_id: str
    checksum: str                          # = sha256(jcs(model_dump(exclude={"checksum"})))
    created: dict                          # {by, strategy_id, at, operator}
    slots: dict = {
      "role": str, "goal": Goal, "inputs": list[SlotInputs],
      "output": {"format": str, "schema": dict|None, "length_budget": str},
      "constraints": {"must": list[str], "must_not": list[str], "style": list[str]},
      "examples": list[dict],               # {input, expected}
      "workflow": list[str], "feedback_protocol": dict,
    }
    freeform_extras: list[dict]             # {id, text, note?, provenance}
    provenance_map: dict[str, dict]         # loc → {source}
    protect_registry: list[dict]            # {loc, class, state, by, at, review_by}
```

规则：**slots 是唯一事实源**；指令清单是编译期派生物（渲染时生成，带 loc 派生 ID）；`protect_class/provenance/created/meta` 为服务端管理字段，任何用户/生成器载荷不得携带（递归校验，见 §4.4）。

### 4.2 Patch v3（`patch.py`）

```python
class Op(BaseModel):
    op: Literal["ADD","DELETE","REWRITE","MOVE"]
    loc: str                                   # 见 §4.3 文法
    content: Any | None = None
    reason: str
    evidence_refs: list[str] = []              # DELETE 必填且非空
    to: dict | None = None                     # 仅 MOVE：{"head":true}|{"tail":true}|{"before":id}|{"after":id}

class Patch(BaseModel):
    schema_version: Literal["3"] = "3"
    patch_id: str                              # 服务器分配的 ULID，不可变（提交时分配并持久化）
    base: {"ir_id": str, "version": int, "checksum": str}
    model_scope: str | None                    # None=基线补丁；"glm5"等=模型 Overlay
    intent: Literal["improve","simplify","fix","protect"]
    ops: list[Op]
    idempotency_key: str
    created: dict
    patch_hash: str                            # sha256(jcs(Patch 去掉 patch_hash/patch_id)) —— 授权绑定用
```

**Patch 执行语义（本轮裁定，全部实现）**：
1. `patch_id`：提交时服务器生成 ULID 并持久化；应用器是纯函数 `f(base_ir, patch) → new_ir`，重放取已存结果（不重算），ID 恒定。
2. **item_id 派生**：`sha256(jcs([patch_id, op_index])).hexdigest()[:10]`（小写 hex，40 bit）。应用时与目标列表既有 ID 冲突 → 追加 2 个 hex 字符直至唯一（同 base 同 patch 状态确定 → 重放安全）。墓碑保证已删 ID 永不复用。
3. **MOVE 锚点**：`to` 必须且只能取 `head/tail/before/after` 之一，否则 `E_MOVE_ANCHOR`；锚点 item_id 必须在目标列表中解析，否则 `E_FIELD_UNKNOWN`。
4. **整项 REWRITE**（freeform 列表项 / slots 列表项）：**全替换语义**——载荷 = 新对象除 `id` 外全部字段；未携带的可选字段即删除（要保留就显式携带）；`id` 永远保持；`provenance` 由系统改写为本次记录（载荷携带服务端管理字段 → `E_PROTECT_FIELD`）。
5. **Overlay 绑定与失效**：渲染管线（§6.3）逐条校验模型线补丁的 `base.checksum`；**不等于当前 IR 版本 checksum 的 Overlay 判为 stale**——排除出渲染、列入 `RenderResult.stale_overlays[]` 并告警；重基（rebase）= 对该 Overlay 跑 iterate 流程重新生成。基线补丁不适用此规则（它们构成 IR 版本链本身）。

### 4.3 loc 文法（`patch.py` 内实现解析器 + 单测）

```
loc         := object_loc | array_loc
object_loc  := "slots" "." segment ("." segment)*
array_loc   := "freeform_extras" "[" item_id "]" ("." ff_field)*
segment     := field | list_select
list_select := field "[" item_id "]"
field       := [a-z][a-z0-9_]*
ff_field    := "text" | "note"
item_id     := [a-z0-9][a-z0-9-]{4,14}[a-z0-9]
```

**op-loc 兼容矩阵**（16 格，代码化为表驱动 + 属性测试全覆盖）：

| op | 标量路径 | 列表容器 | 列表项 | ff 子字段 |
|---|---|---|---|---|
| ADD | ✗ E_ADD_TARGET | ✓ 追加 | ✗ | ✗ |
| DELETE | ✗ E_DELETE_TARGET | 仅空容器 ✓（非空 E_DELETE_NONEMPTY） | ✓（写墓碑） | ✗ E_DELETE_TARGET |
| REWRITE | ✓ | ✗ E_REWRITE_TARGET | ✓ 全替换 | ✓ |
| MOVE | ✗ E_MOVE_TARGET | ✗ | ✓（须锚点） | ✗ |

### 4.4 两阶段应用器（`applier.py`，M1 核心）

```
apply(base_ir, patch, registry) -> (new_ir, events)   # 纯函数
  阶段0 前置：Patch Schema 校验(E_SCHEMA_INVALID)；base.checksum == checksum(base_ir)(E_BASE_DRIFT)
  阶段1 模拟：scratch = deep_copy(base_ir)
    for i, op in enumerate(patch.ops):            # 按序；第 i 条针对前 i-1 条之后的状态
      校验顺序：loc 解析(E_FIELD_UNKNOWN/E_ID_SYNTAX/E_ROOT_FORBIDDEN/E_INDEX_FORBIDDEN)
        → 墓碑(E_LOC_RETIRED) → 保护(E_PROTECT_ENACTED/REWRITE/MOVE/ANCESTOR/FIELD 含载荷递归扫描)
        → op-loc 矩阵(E_*_TARGET/E_MOVE_ANCHOR) → 意图签名一致性(E_INTENT_MISMATCH, §9.4)
      变更 scratch；新增 item_id = 派生(§4.2.2)
    任一失败 → 抛 ApplyError(code, op_index)   # “错误码 @ op[N]”
  阶段2 提交（store 层单事务）：
    UPDATE irs SET current WHERE checksum=base  # 零行命中 → E_BASE_DRIFT（并发竞态防护）
    + 写新 IR 版本行 + 墓碑行 + 幂等记录 + 审计行(audit_entries 同库表)
```

**意图签名**（服务端，不采信声明）：`仅DELETE/MOVE且渲染token下降 → simplify；含ADD约束或REWRITE(goal|role) → improve；evidence_refs引用失败签名 → fix；仅ProtectionChange产物 → protect`。与声明不符 → `E_INTENT_MISMATCH`。模拟前后 checksum 相同且无墓碑变化 → no-op，判 `E_INTENT_MISMATCH`（no-op 非法）。

### 4.5 错误码总表（唯一权威；API 层透传，映射 HTTP）

**核心（应用器/引擎）**：`E_BASE_DRIFT`(409)、`E_SCHEMA_INVALID`(422)、`E_INDEX_FORBIDDEN`、`E_ROOT_FORBIDDEN`、`E_ID_SYNTAX`、`E_FIELD_UNKNOWN`(422)、`E_LOC_RETIRED`(422)、`E_ADD_TARGET`、`E_DELETE_TARGET`、`E_DELETE_NONEMPTY`、`E_REWRITE_TARGET`、`E_MOVE_TARGET`、`E_MOVE_ANCHOR`(422)、`E_PROTECT_ENACTED`(403)、`E_PROTECT_REWRITE`(403)、`E_PROTECT_MOVE`(403)、`E_PROTECT_ANCESTOR`(403)、`E_PROTECT_FIELD`(403)、`E_PROTECT_CONSUMED`(409)、`E_INTENT_MISMATCH`(422)、`E_STALE_OVERLAY`(200 渲染降级标注，非拒绝)、`E_FENCING_STALE`(409)、`E_IDEM_REPLAY`(响应元数据，非错误)。

## 6. 渲染管线与复现

### 6.1 双缓存键

```
RenderCacheKey = sha256(tuple_hash([("ir", ir_checksum), ("overlay", overlay_chain_hash),
                 ("card", model_card_hash),          # ★ 模型卡内容哈希（卡更新即失效）
                 ("renderer", renderer_version), ("template", template_version),
                 ("decode", jcs(decode))]))
EvalCacheKey   = RenderCacheKey + tuple_hash([("model_snapshot", …), ("env", jcs(env7)),
                 ("bench", bench_version), ("baseline", baseline_id),
                 ("judge_model", judge_snapshot), ("judge_prompt", judge_prompt_version),
                 ("judge_decode", jcs(judge_decode)), ("repeats", …)])
```
`tuple_hash` = `sha256(jcs([[k,v],…]))`（带字段名前缀，禁止裸字符串拼接）。**渲染缓存可跨环境复用；评测缓存禁跨环境/跨模型/跨裁判复用**（改任一分量必须未命中——TCK 断言）。

### 6.2 复现三级

| 级 | 条件 | 声明 | 失效 |
|---|---|---|---|
| T1 | 自托管：权重+推理框架+硬件+batch/并行+浮点确定性+tokenizer+拼接模板七分量全记录 | 「所记录环境内逐字节一致」 | 环境任一分量变 |
| T2 | 供应商别名+探针指纹（3 条标准探针的响应哈希，每 7 天巡检） | 「条件复现」 | 指纹变 → 级联失效 |
| T3 | 仅模型名 | 「最佳努力，结论 14 天时效」 | 到期必须重验 |

**标签时效**：model_cards 每个门禁标签必须带 `{bench_version, task_scope, evidence_id, achieved_at, expires_at}`；T2 标签 `expires_at ≤ 巡检周期 + 7 天`。过期标签自动降为「历史证据，需重验」，UI/API 均不得再展示为当前能力。

### 6.3 渲染流程（`engine/render_pipeline.py`）

```
render(ir, model_id) → RenderResult
  1 取基线 IR（scope=null 版本链尖端）
  2 取模型线补丁（model_scope=model_id, status=applied），按 version 排序
  3 逐条：base.checksum != 当前 IR checksum → 该补丁判 stale，排除并记录（E_STALE_OVERLAY 标注）
  4 基线补丁线已构成 IR 本体；模型线在模拟态叠加（复用 applier 的 simulate，保护/墓碑检查照常）
  5 按模型卡渲染 → RenderedPrompt{text, instruction_manifest, cache_key}
```

## 7. 材料接入（本轮新增契约，`blobs.py` + API）

### 7.1 规则
- **唯一入口**：`POST /v1/blobs`（multipart 或 raw body + `X-Blob-Mime` 头）。**禁止**服务端抓取任何外部 URL。
- 服务端计算 SHA-256 并返回 `{blob_id, content_hash, size, mime}`；调用方仅可用 blob_id 引用。
- 限制（默认，可配）：单 blob ≤ 10MB；MIME 白名单 `text/plain, text/markdown, text/csv, application/json, image/png, image/jpeg, application/pdf`；每任务 ≤ 20 个 blob；每租户配额 1GB；TTL 30 天（到期清理任务 + 引用该 blob 的 IR 在渲染结果中标注 `material_expired`）。
- 删除传播：租户删除请求沿血缘标记相关 IR 的材料引用为 `revoked`，不删 IR（内容不可用但结构保留）。

## 8. LLM 客户端与角色矩阵（`llm/`）

### 8.1 客户端
OpenAI 兼容：`POST {base_url}/chat/completions`；支持 `response_format=json_schema`（结构化输出）；超时 120s/次；重试 ≤1（网络类）；**供应商故障 = fail-closed**：任务标 `result_class=degraded` + 明确错误，**禁止静默切换其他模型**。

### 8.2 角色矩阵（默认配置，D2 实测后可换但回避规则不可违反）

| 角色 | 默认模型 | 族 | 说明 |
|---|---|---|---|

## 9. 评测体系（本轮重构核心）

### 9.1 统计单元 EvalCase（取代旧 EvalUnit）

```
EvalCase = { case_id, task_id, model_snapshot, seed, repeat_idx }
case_id  = tuple_hash([("task",task_id),("model",model_snapshot),("seed",seed),("repeat",repeat_idx)])
提示词变体（候选/B1/B2）= 处理因素，在同一 case 内配对比较
```
**聚合顺序**：case 内配对 → 任务层聚合（同任务各 case 的均值/胜率）→ 跨任务配对检验（Wilcoxon 符号秩；二元成功用 McNemar）。禁止跳层；禁止把 repeats 当独立样本（防伪重复）。

### 9.2 主端点（D-1，已裁定）
- **主端点 = 同任务同模型下的机器可判定任务成功率**（配对差异检验）。
- **回退主端点 = 最终产出盲评胜率 vs B1**——仅当任务不可机器判定时使用；两者不得同时为主端点。
- 金标构成约束：**30 个金标任务中 ≥ 24 个必须机器可判定**（exact-match / contains / 单元测试通过 / 数值容差 / checklist 程序判定），≤ 6 个允许人工判定（用于盲评回退路径的验证）。

### 9.3 金标任务 schema（`benchmarks/tasks.jsonl` 每行一个）

```json
{ "task_id": "t-001", "type": "extraction|transform|analysis|draft|code",
  "judge": "machine|human",
  "machine_judge": {"kind": "exact_match|contains|unit_test|numeric|checklist", "spec": {…}},
  "materials": ["bl-…"],
  "prompt_brief": "给外部模型的一句话任务指令（与提示词无关的任务本身）",
  "done_criteria": ["…"], "model_budget": {"max_tokens": 4096},
  "split": "calibration|confirmatory|hidden" }
```
切分固定：校准 10 / 确证 20 / 隐藏 ≥10（隐藏集永不参与调参、预注册与晋升）。

### 9.4 门禁流程
1. **校准集**：调 rubric、定阈值、跑功效分析（MDE、目标功效 0.8、α 0.05）→ 产出 `preregistration.json`（含主端点、基线构建协议、B1 作者时间盒声明、阈值、生效时间戳）→ 冻结。
2. **确证集**：单次运行。逐模型判定：
   - **优化支持**：主端点配对检验过预注册阈值 + 回归集非劣（TOST ε_ni）+ 硬门全过；
   - **兼容**：仅非劣 + 硬门全过；
   - **不通过**：非劣未达或硬门失败。
3. **全局安全闸（分级，本轮裁定）**：S1 严重（安全/合规违规）任一出现 → 整体不通过；S2 硬格式破坏/关键任务回归 → 预注册关键任务集上零容忍；S3 轻微 → 预注册率阈值（二项 CI 下限 ≥ 5% 才判违规）。关键任务清单进预注册。
4. B1 为**时间盒人工基线**：每任务基础撰写 ≤ 15 分钟 + 每模型适配 ≤ 5 分钟；所有结论必须注明「时间受限人工基线」并报告单位成本口径。

### 9.5 裁判证据链（本轮新增）
`EvalRun` 与 `EvalEvidence` 必须记录：`judge_model_snapshot`、`judge_prompt_version`（裁决提示词版本）、`judge_decode`、`reviewer_pool_id`（人工时）、rubric 版本、`reproduction_tier`、逐模型门禁标签。缓存键同步（§6.1）。

## 10. API 与连接器（v1.0-rc）

### 10.1 HTTP 资源（FastAPI，全部挂 `/v1`）

| 资源 | 方法 | 说明 |
|---|---|---|
| `/capabilities` `/schema` `/model-cards` | GET | 能力协商 / 导出 JSON Schema / 模型卡清单（含标签+expires_at） |
| `/blobs` | POST | 材料上传（§7） |
| `/tasks` | POST | 创建 generate/iterate（异步） |
| `/tasks/{id}` `:cancel` `/rubric:confirm` | GET/POST | 状态 / 幂等取消 / rubric 人工锚点（有效期 72h，超时自动 cancelled+通知） |
| `/tasks/{id}/evidence` | GET | EvalEvidence（含裁判链与层级标签） |
| `/score` `/render` | POST | L1+小规模 L2 同步（10s 预算）；超限 → 202+task_id 异步接管 |
| `/sessions` `/{id}/events` `/{id}/patches` | POST | 开会话 / 推轮次（turn_seq 单调，乱序 E_EVENT_ORDER）/ 按 suggestion_id 应用 |
| `/sessions/{id}/events` | GET | **拉取游标** `?after_event_seq=N`（推送失败的兜底） |
| `/sessions/{id}` `/budget` | GET | 会话状态 / 预算余量 |
| `/protection-requests` `/model-card-requests` | POST | 治理请求（只提交，批准在系统内人工通道） |

### 10.2 幂等与并发（实现要点）
- 唯一约束 `(connector, tenant, op, idempotency_key)` + `request_hash`；同键异载荷 → `E_IDEM_PAYLOAD_MISMATCH`；重放返回**首次结果原状态码**（响应头 `X-Idem: replay`）；执行中重放 → 200 + 当前任务视图；键 TTL 72h。
- **fencing**：sessions 用 epoch；tasks 用 `fencing_token`（单调）。worker 提交前核对 token，落后 → `E_FENCING_STALE`（409）丢弃提交——取消先发生时，在途 worker 的提交全部失败。

### 10.3 事件投递（修订：持久化 + 死信 + 重放）
- 事件先落 `events` 表（outbox）：`task.state_changed`（规范事件）+ `rubric.confirmation_required` + `suggestion.proposed`；completed/failed 为兼容别名。
- 推送：指数退避 + 抖动，**最多 5 次** → 进 DLQ（state=`dead`）；管理端点支持重放。
- **拉取兜底**：`GET /sessions/{id}/events?after_event_seq=N` 客户端可自愈——推+拉双通道后，才允许声称 at-least-once。
- 签名：HMAC-SHA256 输入 = 事件 JCS **去除 signature 字段** + key_id；时间容差 ±5min；轮换期双钥（旧钥宽限 24h）。

### 10.4 在线建议（suggestion_id 不可变）
推送 `suggestion.proposed = {suggestion_id, patch_hash, 四元组{session_epoch, base_checksum, intent_hash, context_hash}, 证据, 信号类别}`；应用时 host 只提交 `{suggestion_id, 四元组}`，服务端取原 Patch 核 hash 与四元组。语义门控：寒暄/进展不作废；材料/目标/约束/纠正 30s 去抖后重排；不确定保守作废；作废率 >60%（滑动 50）告警。

### 10.5 MCP 绑定（18 工具，修正计数）

`pg_capabilities, pg_schema_get, pg_model_cards, pg_generate, pg_iterate, pg_task_status, pg_task_cancel, pg_rubric_confirm, pg_evidence_get, pg_score, pg_render, pg_session_open, pg_turn_record, pg_patch_apply, pg_session_status, pg_budget_read, pg_protection_request, pg_modelcard_request` — **共 18 个**。TCK 断言：18 工具逐一契约 + 9 能力全覆盖 + 与 HTTP 同输入同输出同错误码。禁止再出现「13 工具」的过期表述。

### 10.6 接入灰度（四段）
沙箱 TCK 全绿 → 最小权限生产（discovery+单能力，≤5 任务/日，回调白名单）→ 指标观察 ≥1 窗 → 逐能力提升配额（events.v1 永远最后）。
