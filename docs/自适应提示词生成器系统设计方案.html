自适应提示词生成器：系统设计方案

一套可适配大多数 AI Agent 场景的提示词生成系统：以「结构化中间表示 + 生成-评估-选择循环 + 逐模型编译」为骨架，以「评估日志驱动的分层自学习」为飞轮。

v0.1 讨论稿 8 个功能模块 4 条关键流程 4 层自学习闭环 2026-10-24

方案概述：一句话说清这套系统

系统的核心对象不是「提示词文本」，而是一份结构化的提示词中间表示（Prompt IR）。文本只是 IR 在某个目标模型上的「渲染结果」。所有生成、改进、评估、学习都发生在 IR 层面，只在最后一步才编译成面向目标模型风格的成品。

为什么这个决定最重要？因为你提的五条需求，恰好分别卡在五个不同的工程难点上，而 IR-first 是同时解开它们的同一把钥匙：

  • 「迭代 vs 从零」——需要把现有提示词「读懂再改」而不是「重写一遍」→ IR 提供可 diff、可追溯的结构；
  • 「补遗漏、删冗余、删未提及」——需要知道改了哪一条、删了哪一句 → IR 里的指令是带 ID 与出处的原子单元，才能做逐条归因和消融；
  • 「适配不同大模型的风格」——同一份意图在不同模型上要长成不同样子 → IR 与渲染分离，一份 IR 编译出 N 份模型特化文本；
  • 「沉淀更优的生成方式」——学习的对象是「怎么生成」而不是「生成了什么」→ 沉淀物（策略卡、示例对、偏好数据）全部挂在 IR 的编辑操作上，可统计、可复放；
  • 「持续同步优化」——优化不能靠一次性人工调参 → 把「评估-排序」的日常日志直接变成自训练的数据源。

整份方案可以压缩成一张图：上半部分是运行时链路（三条入口路径，共用一套生成-评估-选择引擎），下半部分是离线飞轮（把运行时产生的证据蒸馏成生成能力的升级）。

一 / Principles

设计立场：三条从上一轮分析直接继承的铁律

上一轮对 WorkBuddy 与七个开源项目的拆解，结论里有三条对本设计具有约束力，先立在这里，后面所有模块设计都不与之冲突。

铁律一：提示词没有普适最优解，只有针对特定模型的最优解。（DSPy 的实证结论：同一程序在不同模型上被优化成不同提示词。）所以本系统从不追求「一段万能好提示词」，每个候选都必须绑定目标模型评测；换模型 = 重新编译 + 重新评测。
铁律二：评估信号的上限就是优化效果的上限。（优化器会精准地优化你给的指标，包括你写错的部分。）所以评估模块 M5 是全系统的「心脏」而非附件，评分依据必须从用户意图自动生成（锚定式 rubric），不允许拍脑袋打分。
铁律三：相对优于绝对，结构优于措辞。（成对比较比绝对打分稳；声明式结构比自然语言祈使句可靠。）所以排序一律用交换顺序的成对裁决；一切可以结构化的约束（格式、schema、禁令清单）都收进 IR 的结构字段，而不是写成散文。

二 / Architecture

总体架构：四层八模块

模块间只有一条主数据流：M1 理解 → M4 生成 → M5 评估 → （M6 监测）→ 交付，其余模块都是这条主干的服务者或观察者。这样设计的好处是每条流程（A/B/C/D）都只是对同一条主干的不同「进入方式」和「触发时机」，不存在为某个需求单独发明的旁路逻辑。

三 / Modules

模块职责详解

M1意图解析与槽位抽取把「人话」翻译成「结构」，是一切后续环节的地基
职责
读取用户多轮提问与上下文（以及可选的既有提示词），抽取成一份带置信度的意图框架（Intent Frame）：任务类型、角色、目标与完成标准、输入材料、输出格式、约束与排除项、示例、目标模型。
输入
多轮对话流；既有提示词（迭代模式下的种子）；用户上传材料。
输出
Intent Frame（JSON，每个槽位附 confidence 与 source_turn 出处）；「缺失槽位清单」，按信息增益排序。
关键技术
结构化抽取（function calling / JSON Schema 约束输出）；槽位置信度估计；澄清提问选择器——只对「缺失且阻塞生成」的槽位发问，每轮最多 2–3 问，问完即走，避免把生成器做成审讯室。迭代模式下额外做种子反解：把既有提示词逆向解析成 IR，与对话意图做 diff。
边界
不做生成、不做评估；对用户文本一律按「数据」处理（见 M8 注入防护），抽取结果只进结构字段，不进指令区。
M2提示词资产库与版本管理所有提示词以 IR 形式入库，文本只是其投影
职责
存储、检索、版本化所有 IR。冷启动时提供同任务类型的骨架模板与成功示例；迭代时提供「父版本」与历史评测，用于回归保护。
数据组织
按「任务类型 × 目标模型」建索引；每条 IR 保留版本树（谁、用什么策略、基于什么证据改出来的）；语义化版本：补内容 = minor，删冗余 = patch，结构调整 = major。版本树是 M7 归因分析的原材料——没有它，「沉淀更优生成方式」无从谈起。
关键技术
向量检索（找相似任务的成功 IR 做参考）；指令级血缘标注（每条 instruction 记录来源：用户说的 / 种子里的 / 生成器加的）。
边界
不评分、不淘汰——晋升与降级由 M5+M7 决定，库只负责忠实记录。
M3目标模型适配层一份 IR，N 种渲染；模型差异被隔离在这一层
职责
维护每款目标大模型的模型卡，并把 IR 渲染成该模型偏好的表面形式。
模型卡内容
结构偏好（XML 标签 vs Markdown 层级 vs 纯文）、系统提示词惯例、指令位置敏感性（首尾 vs 中段）、否定式指令的遵循强度、输出格式约定、工具调用格式、上下文预算与 token 换算率（注意是 token 不是字）、已知的怪癖与禁忌。
关键技术
渲染器 = 模板 + 模型卡参数；同构校验（渲染前后 IR 语义等价性检查）；模型卡本身也是可学习资产——M7 发现某模型对某类指令衰减快，就回写进模型卡。模型卡格式建议直接采用「Skill + references」的组织方式（参考 WorkBuddy 的渐进式披露），生成时按需加载。
边界
只做「翻译」，不做「优化」——措辞优劣由 M5 判定；换模型必须重新评测，不允许「渲染完直接用」。
M4生成引擎双模式输入、多策略出候选、补丁式输出
职责
产出候选方案。两条路径：从零模式（Intent Frame + M2 检索的骨架 → 生成完整 IR）；迭代模式（种子 IR + 意图 diff → 生成编辑补丁）。
多策略候选
每次产出 N 个（默认 4）候选，刻意用不同生成策略拉开多样性：① 骨架模板填充（结构派）；② 模仿资产库最优同类 IR（范例派）；③ 自由撰写后回填 IR（自由派）；④ 极简约束派（只保留必需项）。策略 ID 写入候选元数据——M7 靠它统计「哪派在什么场景赢面大」。
补丁式输出
迭代模式不整篇重写，而是输出原子操作序列（见第四节）：ADD / DELETE / REWRITE / REORDER。这是「补充遗漏、删除冗余、删除未提及」的执行载体——每条改动独立可评审、可回滚、可归因。
关键技术
生成用的元提示词本身是一个带版本的 IR 资产（自举，详见 M7-L2）；few-shot 示例从 M2 检索而非写死；输出用结构化约束保证是合法 IR。
M5评估与排序全系统的心脏：三级信号，逐级加码
职责
给候选排序、给现有版本把关、给「删冗余」提供证据。三级信号，成本递增，逐级淘汰：
级别手段成本拦什么
L1 静态检查规则引擎：槽位完整性、指令自相矛盾检测、token 预算、禁词与风险扫描、格式合法性零调用结构性硬伤
L2 成对裁决LLM 裁判对候选两两比较；交换 A/B 顺序各裁一次，两次结论一致才计分；评分依据是 M1 的意图框架自动生成的可勾选 rubric，不允许裁判自由发挥中措辞与结构优劣
L3 执行验证把候选真正投到目标模型上跑抽样用例，量任务指标；开放式任务用 Elo 锦标赛累积排名高（可选）「说得好≠跑得好」
关键设计
① rubric 从 goal.done_criteria + constraints 自动生成，保证「评的就是用户要的」；② 成对 + 交换顺序，压制裁判的位置偏差与长度偏好；③ 裁判模型尽量与生成器异族，规避同族自评偏好；④ 每一次裁决（谁赢谁输、为什么）都落日志——这份日志天然就是偏好学习数据，是 M7 自训练最便宜的燃料。
消融模式
冗余判定专用：逐条摘除指令 i，重跑 L2/L3，得分不变 ⇒ 冗余候选；得分下降 ⇒ 有效指令。为控制成本，只对「疑似冗余」（重复语义、低引用、用户从未触发）做消融，不做全量。
M6会话内动态改进器旁路监听，异步出补丁，不阻塞对话
职责
满足「多轮对话中读取提问与上下文、动态改进」：持续监测运行中的对话，识别改进信号，触发 M4 的补丁流程。
信号规则（v1 清单）
  • 约束失效：用户重复同一要求 ≥ 2 次 → 候选补丁：把该指令移位（首/尾）或升格为逐条检查清单；
  • 目标偏移：用户出现纠正语（「不对 / 我说的是 / 别」）→ 重新走 M1 抽取，diff 后出补丁；
  • 材料更新：用户上载新文件 / 新引用 → 更新 inputs 槽位；
  • 预算越界：输出连续超长 / 超格式 → 收紧 budget 约束；
  • 上下文吃紧：token 余量低于阈值 → 触发删冗余压缩 pass；
  • 任务切换：意图框架的任务类型变化 → 建议切换 IR 而非硬改。
应用策略
异步生成、静默评估、显式应用：补丁在后台生成并过 L1/L2，分数显著提升才提示用户「建议应用此改进」，用户确认或达到自动阈值后生效；不满足则攒到会话结束统一复盘。绝不在线上对话中同步阻塞。
边界
M6 只负责「发现信号 + 触发流程」，补丁的生成与评估仍然复用 M4/M5，避免第二套逻辑。
M7蒸馏与自学习分四层渐进，先便宜后昂贵；每一层都以上一层为门槛
职责
把运行时产生的证据（版本树、评测日志、消融结论、会话轨迹）蒸馏成生成能力的升级。四层递进，成本与风险同步上升：
层级沉淀物更新什么触发风险
L0 经验记忆会话级反思笔记：本任务×本模型什么有效生成时的上下文参考每次会话结束极低
L1 策略沉淀策略卡：{触发模式, 任务类型, 模型, 编辑操作序列, 平均增益, 样本量, 状态}M4 的策略库与 few-shot 示例对；M3 模型卡回写每日/每周批处理低
L2 元提示词进化生成器自身元提示词的新版本（挑战者）M4 的「大脑」本身，冠军/挑战者机制周级，先过冻结基准中
L3 权重蒸馏SFT/DPO 训练 checkpoint一个专门的小型「提示词改写器」模型数据量达标后（万级偏好对）高，需护栏
晋升规则
策略卡从 experimental → promoted 需满足：跨 ≥ N 个独立会话 + 增益统计显著 + 冻结基准回归通过。禁止单例晋升——一个案例好不构成知识。
L3 的燃料
两个来源：① M5 的成对裁决日志（每场 A/B 比较都是一对现成的偏好样本，零额外标注成本）；② 高分 IR 的生成轨迹（对话上下文 → 编辑补丁）。训练后走影子部署 → 灰度 → 全量，任何一步回归即回滚。
M8编排、安全与治理预算看门人 + 注入防护 + 血缘审计 + 人工闸门
职责
四件事。① 模式路由：判定走从零 / 迭代 / 在线观察哪条入口；② 预算管理：每会话的调用与 token 上限，评估级别自动降档（L3→L2→L1）而非超支；③ 注入防护：M1 读取的一切用户文本按数据隔离——生成器自己的元提示词里，指令区与数据区显式分离，杜绝用户对话里的内容劫持生成逻辑（继承 WorkBuddy 六层堆栈的分区原则）；④ 审计与闸门：每个 IR 版本可追溯到策略、证据、评测分；L2 元提示词晋升与 L3 训练上线必须过人工审核门。
多租户
策略池分「全局公共」与「租户私有」两层，个人偏好不污染通用策略（详见风险 R5）。

四 / Data Model

数据模型：Prompt IR 与原子编辑操作

IR 是全系统唯一的主数据对象。下面给出足以开工的字段草案——实现时可以简化，但有三个字段不可省：instruction_id（原子性）、provenance（出处）、evidence（证据），因为它们分别是「删冗余」「删未提及」「学习归因」的前提。

IR = {
  meta:      { id, version, parent_id, task_type, target_model,
               created_by: "zero|iterate|online", strategy_id }
  slots: {
    role:            "角色设定",
    goal:            { outcome, done_criteria[], non_goals[] },
    inputs:          [ { ref, type, note } ],        // 材料与引用
    output:          { format, schema?, length_budget },
    constraints:     { must[], must_not[], style[] },
    examples:        [ { input, expected } ],
    workflow:        [ "步骤…" ]                      // 可选
  }
  instructions: [                                  // 原子指令单元
    { id: "INS-07", text: "…",
      provenance: "user_turn_3 | seed | gen:s11",  // 血缘：谁带来的
      ablation:   { tested: true, delta: -0.8 },   // 消融证据
      status:     "active | suspect | retired" }
  ]
  evidence:  { eval_history: [...], usage_stats: {...} }
  rendered:  { model_id: "…", text: "…", checksum } // 渲染缓存，可重建
}

Patch = [ OP, … ]   // 迭代模式的输出，而非整篇重写
  OP = { op: "ADD",     slot, content, provenance, reason }
     | { op: "DELETE",  ins_id, reason, evidence }        // 冗余/未提及的删除都走这里
     | { op: "REWRITE",  ins_id, new_text, reason }
     | { op: "REORDER", ins_id, position, reason }        // 例：中段→尾部，对抗遗忘
     | { op: "COMPILE", model_id }                        // 渲染出口，最后一步才发生

这套模型如何精确对应你的三个动词：

  • 补充遗漏——M1 从最新对话中抽出新出现的槽位或约束，与当前 IR diff，产出 ADD；provenance 记为具体轮次，日后可查「这条是谁说的」。
  • 删除冗余——语义相似度 + 消融测试定位疑似冗余指令，DELETE 必须附带消融证据（「摘掉它分数不掉」），不允许凭感觉删。
  • 删除未提及——provenance 系统的直接应用：凡是 provenance = gen:（生成器自己加的）且用户全程未互动、评测也无增益的指令，就是「未被提及的内容」，标记 suspect，经消融确认后删除。

五 / Key Flows

四条关键流程

四条流程共用同一条主干（M1→M4→M5），差别只在入口与触发时机。每条流程都给出触发条件、步骤与出口判据，可直接当作开发任务拆解的依据。

流程 A · 冷启动：从零搭建

触发：用户无既有提示词。目标：产出 v1.0 IR 并入库。

  1. 意图抽取：M1 解析对话 → Intent Frame（带置信度）；置信度低的关键槽位进入澄清队列。
  2. 澄清循环：按信息增益挑 2–3 个阻塞性问题发问（≤ 2 轮）；用户不答就用合理默认值并显式标注「假设」，绝不卡死等输入。
  3. 骨架检索：M2 按任务类型检索相似成功 IR，取其结构做骨架、其示例做 few-shot 参考。
  4. 多策略生成：M4 用 4 种策略各产 1 个候选 IR（策略 ID 入元数据）。
  5. 三级评估：L1 静态过滤 → L2 交换顺序成对裁决 →（用户开启「深度模式」时）L3 在目标模型上跑抽样用例。
  6. 渲染交付：冠军候选经 M3 按目标模型卡 COMPILE → 展示「成品文本 + 背后的 IR + 评审证据」三件套。
  7. 入库：v1.0 入 M2，血缘、策略、评测分一并落盘——这是未来学习的原材料。

出口判据：rubric 全项通过 + 用户确认。产物：IR v1.0 + 渲染文本 + 证据包。

流程 B · 迭代：基于既有优质提示词改进

触发：用户提交既有提示词（或从资产库选父版本）。目标：可审计的增量改进，且不伤害既有优点。

  1. 种子反解：M1 把既有提示词逆向解析为 IR（这一步本身就用「删未提及」的逆过程：为每条指令建立 provenance=seed 的血缘）。
  2. 意图 diff：对话中体现的最新意图 vs 种子 IR → 生成三张清单：缺失槽位 / 冲突指令 / 疑似冗余。
  3. 补丁生成：M4 产出补丁序列（多个候选补丁包并行），每条操作带 reason 与预期收益。
  4. 回归保护：候选补丁必须在「父版本原本就通过的用例」上不回退，在「新意图用例」上有提升——两条都满足才算赢。这是迭代模式的灵魂：改得差不如不改。
  5. 呈现与确认：以 diff 视图呈现给用户（加了什么、删了什么、为什么、证据是什么），确认后合并。
  6. 版本落地：按操作类型做语义化版本升级（补 = minor，删 = patch，结构 = major），更新版本树。

出口判据：回归全绿 + 新用例提升 + 用户签字。产物：IR v(n+1) + diff 报告。

流程 C · 会话内动态改进（旁路模式）

触发：M6 的信号规则命中（重复指令 / 纠正语 / 新材料 / 超预算 / 上下文吃紧）。约束：绝不阻塞正在进行的对话。

  1. 信号检测：每轮对话后，M6 用轻量规则 + 抽取器扫一遍（单次、便宜），不命中即结束，零额外成本。
  2. 异步补丁：命中 → 后台触发流程 B 的第 2–4 步（diff、补丁、评估），用户侧无感。
  3. 门槛判定：补丁过 L1+L2 且增益超过阈值 → 弹出「建议应用」；未超阈值 → 记入会话待办，会话结束统一处理。
  4. 应用与回滚：用户确认（或达到自动应用阈值，如连续两轮同一信号）→ 应用补丁 → 目标模型侧生效；下一轮输出未见改善 → 自动回滚并记入反思。
  5. 会话复盘：会话结束，M7-L0 生成反思笔记：本会话哪类信号、哪种补丁、效果如何——飞轮的最底层原料。

出口判据：每条补丁要么被应用并验证、要么被明确否决（否决也要留痕，负样本同样是学习材料）。

流程 D · 蒸馏与自训练（离线飞轮）

触发：定时批处理（日/周级）。目标：让「生成方式」本身变好，并防止越学越歪。

  1. 证据聚合：收集全部（对话上下文 → 补丁 → 评测分 → 用户反馈）轨迹，按任务类型 × 目标模型分桶。
  2. 归因分析：统计各策略 / 各编辑操作在各桶上的增益——产出候选策略卡（experimental 状态）。
  3. 反思蒸馏：用最强的反思模型读失败案例与成功案例，产出自然语言形式的改进建议——这些建议就是元提示词的修订提案（GEPA 式：反馈是文字，不只是分数）。
  4. 晋升闸门：候选策略卡与新元提示词必须在冻结基准集上跑冠军/挑战者；挑战者胜出幅度超阈值才晋升，否则丢弃。人工审核门在此处介入。
  5. 权重蒸馏（可选，数据达标后）：用裁决日志构造偏好对（赢方/输方）做 DPO；用高分轨迹构造 SFT 对微调小型改写器；KL 约束 + 提前停，防止偏离基座太远。
  6. 影子验证：新能力先影子运行（只记录不生效），对比线上冠军的表现；通过 → 灰度 → 全量，任一环节回归即回滚。

出口判据：冻结基准不回退 + 线上指标改善 + 审计链完整。任何一步失败都能一键回退到上个冠军。

六 / Learning Loop

自学习闭环：从日志到能力

「蒸馏与自学习」最容易犯的错是把四层混为一谈、直接上微调。分层的原因是风险与可逆性完全不同：L0–L2 只改提示词层的资产，出问题回滚即愈；L3 动权重，回滚成本高、且有自训练坍缩风险（模型在自己输出上循环训练导致分布退化）。所以护栏必须写进设计：

  • 数据配比上限：自生成数据在训练集中占比设硬顶（例如 ≤ 30%），真实用户轨迹与人工核验样本必须保持主体；
  • 冻结基准：一套从不参与训练的评测集，每次晋升必跑，回归即拦截；
  • 多样性巡检：训练对的语义嵌入做离散度监控，分布收窄（全都长得像）即告警；
  • 负样本保留：被否决的补丁、失败的策略照常入库，防止系统只记住成功路径而丧失判别力；
  • 人工审核门：L2 元提示词晋升与 L3 上线永远需要人签字——这是「持续同步优化」不变成「持续同步漂移」的最后一道闸。

七 / Model Selection

模型选型：待定不等于悬空——先定角色，再定型号

「模型待定」的正确处理方式不是等，而是把系统对模型的要求写成规格。本系统对 LLM 的需求其实是四个角色，可以由一至多个模型承担：

角色干什么硬性要求调用量级选型倾向
生成器意图抽取、候选生成、种子反解（M1/M4）32k+ 上下文、结构化输出、强指令遵循每任务数次中高价位的强推理模型
裁判成对裁决、rubric 核对（M5-L2）输出一致性（低温度）、与生成器异族为佳每任务 2N 次中低价位、稳定的模型
反思器离线失败归因、修订提案（M7）最强可用推理周级批处理旗舰模型（只在飞轮里用，摊薄成本）
目标模型被生成提示词驱动的最终 AI（用户侧）无要求——任意视用户而定由场景决定，逐个建模型卡

三条选型经验直接写进约束：① 裁判与生成器尽量异族——同族模型自评有系统性偏好，上一轮拆解 gpt-prompt-engineer 时已确认这是单一裁判的最大隐患；② 贵的模型用在低频高层——反思器只在周级批处理里调用（GEPA 的 reflection_lm 模式：贵模型指挥，便宜模型干活）；③ 目标模型永远是被测对象——任何候选提示词未经目标模型实测（L3）就宣称「适配」，都只是 L2 层面的推断，对外话术要如实区分。
