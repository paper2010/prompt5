v0.4 总览：从「方向正确」到「Schema 可写、用例可编」

第三轮复审的结论是「有条件通过、暂不签发 S0 关闭」——判得对。它指出的 6 个 P0 项里，有 3 个（loc 示例矛盾、预校验冲突、保护类绕过）是会让实现者写出两套互相打架的代码的契约级缺陷。v0.4 的全部修订都服从一个检验标准：复审者拿着本版去写 JSON Schema、用例集和应用器，不需要再做任何设计决策、也不会遇到两个条款打架。

0.1 逐条落实对照表

#复审意见级别修改内容修改理由
1loc 文法与 freeform_extras 示例矛盾（形式不符、ID 大写短位、「违法」却标「允许」） P0 §1.1 文法升 v1.1：新增 array_loc 产生式，数组根直接挂 [item_id]；补 field 与 item_id 词法（全小写 6–16 位）；删除矛盾示例，重写合法/非法示例集，非法项逐一绑定错误码。 矛盾示例会直接导致 Schema 与用例集无法编写；数组根需要自己的产生式而非借用对象根的形式。
2「预校验全部 loc」与「按序执行」冲突：新建项无法被后续 op 引用 P0 §1.3 改为两阶段执行模型：静态预校验只留 CAS/幂等/结构三关；loc、墓碑、保护、兼容性校验全部移入「模拟阶段」，在副本上逐条针对中间状态校验；模拟通过才原子提交。同时废除同 loc 单操作禁令，新增项可被本 Patch 后续 op 修改。 模拟执行天然解决「loc 在初始 IR 不存在」的矛盾，且保留原子性；同 loc 禁令在模拟模型下已无必要——先删后改会被墓碑精确拒绝，先改后删语义确定。
3enacted 保护项可经 REWRITE/MOVE 绕过（只防删、不防语义削弱） P0 §3 升 v1.1：enacted 对普通 Patch 完全只读——DELETE/REWRITE/MOVE 全拒；新增祖先保护（改父对象间接改写子项 → 拒绝）；补 E_PROTECT_REWRITE / E_PROTECT_MOVE / E_PROTECT_ANCESTOR / E_PROTECT_FIELD；修改须经 ProtectionChange 批准后生成带授权标记的补丁。 保护的设计目的是「安全/硬格式约束不被自动化削弱」——只拦 DELETE 恰好放过最隐蔽的削弱路径；只读化是唯一完备的口径。
4T1「逐字节一致」超出权重快照能力（算子、硬件、batch、tokenizer 未钉死） P0 §4 T1 重定义为「受控环境内逐字节一致」：环境七分量（权重/推理框架/硬件/并行与 batch/浮点确定性/tokenizer/拼接模板）全部可记录可钉死才归 T1；任一分量不可固定 → 自动降 T2，禁止手动标 T1；捕获清单同步扩容。 GPU 非确定性算子与服务端实现变化会让「钉权重≠钉输出」；把环境作为 T1 的定义成分，声明与能力严格对齐。
5P0a 主比较无基线定义，预注册阈值没有分母 P0 §2 新增基线节：主基线 B1 = 人工提示词（隔离作者、盲写、同材料同模型同格式）；探索基线 B2 = 单策略直出。主比较 = 冠军 vs B1；盲评协议（随机顺序、无来源标记）与基线构建协议并入预注册模板；预算不足时降级 B2 为主基线，该降级本身也须预注册并标注于结论。 三种候选基线会产生完全不同的结论，必须唯一指定；选人工基线是因为系统价值主张正是「超过人工水平」，单策略基线只能作探索对照。
6「每轮作废在途补丁」造成补丁饥饿 P1 §6.1 语义变化门控：新轮先分类（寒暄/进展汇报 → 不作废；材料/目标/约束/纠正 → 作废重排；不确定 → 保守作废）；去抖窗口 T=30s 合并连续变化；新增「作废率＞60% 滑动告警」。 无条件作废在多轮对话里等价于「永远生成不出建议」；用语义判定替代轮次判定，安全性由「不确定即作废」兜底。
7P0b 只验「无回归」，no-op 补丁也能过门禁 P0 §5 补丁意图分类：创建时声明 improve / simplify / fix / protect，各类绑定各自成功判据（improve 须最小效应 + 非劣；simplify 须非劣 + token 降幅；fix 须签名消除 + 非劣）；无声明或无可测变化 → 判失败不计入成功样本；P0b 出口按意图分报成功率。 「删冗余」类补丁的质量中性是设计目标而非失败，用单一改善门会误伤它；按意图定义成功才能同时拦住 no-op、放行合法简化。
8在线可观测性缺指标，两率无法运营 P1 §6.2 指标表：建议产出率、作废率、人工采纳率、采纳后改善率、误伤率、误回滚数、P95 时延、单任务成本（token + 人时摊销）全部给出定义/分母/窗口与告警线。 没有分母与窗口的指标无法判定运营健康，门禁数字也无法复核。
9Patch 链事务：拆 Patch 后用户可见中间状态 P2 随意见 2 的修复消解：同 loc 多 op 已合法，多步修改不再需要拆链；链式事务从待办清单移除（需求消失），跨补丁分组未来如有实证需求再立项。 复审的前提是「若坚持拆链」——两阶段模型使该前提不成立；不为消失的需求预留半成品语义，避免引入新复杂度。
10应用器放在 P0a 拉长关键路径 P2 §7 调整：从零生成确实不需要 Patch 应用器——产品集成移至 P0b 首个交付物；轨 A 规范交付物仍含参考实现 + 用例集（S0 审计照常覆盖），解冻声明所需的「应用器通过用例集」由参考实现满足。 规范与实现解耦：审计要的是契约正确性的证据（参考实现），P0a 产品路径只需 IR 直生 + 渲染 + 评测。
11审计日志「只增不改」缺防篡改证明 P2 §6.3 哈希链台账：每条 entry 含 prev_hash / entry_hash / 签名；WORM 或 append-only 存储；链头哈希定期外部锚定；验证程序 = 重算链 + 验签；P1 出口增加篡改/删改/乱序三类注入用例。 「只增不改」是约定不是证据；审计结论（含保护类、晋升、数据血缘）的可信度依赖防篡改证明。
12冻结金标不能永久复用，需轮换与隐藏集 P2 §7 P2 增补：隐藏测试集 ≥10 任务从不参与调参与晋升；确证集季度换血 25%（校准集不动）；旧结论绑定 bench 版本，换血即失效需重证；轮换程序写入评测规范。 长期反复用同一冻结集会让系统（尤其 L2 元进化）对它产生适应性过拟合；轮换让「冻结」保持含义。

0.2 未变更项清单（与前版保持一致）

  • 保留校准 10 / 确证 20 物理切分与「先校准 → 预注册 → 单次确证」时序；Wilcoxon / McNemar / TOST / Holm / Krippendorff α ≥ 0.67 全套统计规则（§2 仅新增基线定义）。
  • 保留checksum = SHA-256(RFC 8785 JCS(IR\{checksum}))；稳定 ID = hash(patch_id, op_index) 确定性派生；墓碑永不复用。
  • 保留两态三权一周期（proposed/enacted、批准权仅用户/管理员、90 天复核、保护滥用率审计）——v1.1 只是把保护从「删除豁免」升级为「完全只读」。
  • 保留T2 / T3 定义与失效策略；§0.2 两声明（可复现 / 可确定性重放）冻结门禁不变，解冻时点 = S0 审计 + 参考实现过用例集。
  • 保留十类输入源信任边界、五维人时预算框架、DPO 主目标 = Patch 序列预测、权重层不承诺撤销、同族裁判触发式标定。

一 / loc & Executor v1.1

loc 文法与执行模型修订（落实意见 1、2、9）

1.1 loc 文法 v1.1：修复三处矛盾

# loc 文法 v1.1 —— v0.3 的对象根形式不再套用在数组根上
loc         := object_loc | array_loc
object_loc  := OBJECT_ROOT "." segment ("." segment)*
array_loc   := ARRAY_ROOT "[" item_id "]" ("." ff_field)*
OBJECT_ROOT := "slots"
ARRAY_ROOT  := "freeform_extras"          # 数组根：根即列表，直接挂 [item_id]
segment     := field | list_select
list_select := field "[" item_id "]"
field       := [a-z][a-z0-9_]*             # slots 下字段（词法本版补齐）
ff_field   := "text" | "note" | "provenance"   # 自由项可改子字段；protect_class 不可经普通 loc 触达
item_id     := [a-z0-9][a-z0-9-]{4,14}[a-z0-9]  # 6–16 位、全小写、首尾非连字符、永不复用

# ── 合法示例 ─────────────────────────────────────────
# slots.goal.outcome                     标量路径
# slots.constraints.must[c-must-001]     列表项
# freeform_extras[f-a1b2c3]              数组根直接选条目（v0.3 矛盾写法已修正）
# freeform_extras[f-a1b2c3].text         自由项正文，可 REWRITE

# ── 非法示例 → 错误码 ───────────────────────────────
# freeform_extras[F-3].text              → E_ID_SYNTAX       （大写 + 长度不足）
# freeform_extras.items[f-0001]          → E_FIELD_UNKNOWN   （数组根没有伪字段）
# freeform_extras[f-a1b2c3].protect_class → E_PROTECT_FIELD （保护字段不可普通 loc 改）
# slots.constraints.must[0]             → E_INDEX_FORBIDDEN （下标寻址）
# slots.meta.version                    → E_ROOT_FORBIDDEN  （越权根）

1.3 两阶段执行模型：取代「静态预校验 + 按序执行」的冲突组合

理由与旧条款的关系：v0.3 的四关校验中，CAS 与幂等、结构校验本质是静态的，保留在「前置阶段」；而 loc 解析、墓碑、保护、兼容性四项必须针对中间状态判断，移入「模拟阶段」。冲突由此消解，原子性不变。E_LOC_CONFLICT 随「同 loc 单操作禁令」一并退役（见 §8 核查表）。

二 / Baseline

P0a 基线定义（落实意见 5）

主基线 B1 = 人工提示词。每任务 1 份，由与评测团队隔离的提示词作者编写，盲写（不接触系统输出），使用与候选完全一致的材料、目标模型与输出格式要求。选择人工基线的理由：系统的价值主张就是「稳定超过非专家的手工水平」，单策略基线只能证明「评估循环有价值」，无法证明产品主张。
要素定稿
B1 主基线人工盲写；预计每任务 10–16 分钟，30 任务合计 5–8 人时，并入轨 B 预算（总估由 25–45 调整为 30–53 人时）
B2 探索基线骨架模板单策略直出（无评估循环）；仅作探索性对照，用 Holm 校正，不入主比较
主比较冠军 vs B1，配对 Wilcoxon（任务层面），阈值预注册
盲评协议3 名评审只见渲染文本、随机顺序、无来源标记；B1 与候选同场同 rubric 评分；评审不可兼任基线作者
预注册扩展预注册模板新增字段：基线构建协议、作者隔离声明、B1 样本封存时间戳
预算不足降级B1 无法落实 → 主基线降为 B2，降级决定本身须在确证前预注册，且所有对外结论强制标注「基线为单策略自动生成」

三 / Protection v1.1

保护类：从「删除豁免」升级为「完全只读」（落实意见 3）

  1. 只读化：enacted loc 对普通 Patch 的 DELETE / REWRITE / MOVE 一律拒绝（E_PROTECT_ENACTED / E_PROTECT_REWRITE / E_PROTECT_MOVE）。
  2. 祖先保护：op 目标若是任一 enacted loc 的祖先路径（如改写 slots.goal 整对象而其 done_criteria[c-002] 已 enact）→ E_PROTECT_ANCESTOR，防止「改父对象」间接改写受保护子项。
  3. 保护字段不可触达：protect_class、protect_registry 相关字段不进普通 loc 命名空间（E_PROTECT_FIELD）。
  4. 授权通道：确需修改 enacted 项 → 提交 ProtectionChange（改什么/为什么/证据）→ 用户或管理员批准 → 系统生成带 protection_authorization_id（绑定 loc、op 类型、有效期）的授权 Patch → 应用器仅凭匹配且未过期的授权放行。
  5. 滥用审计升级：保护滥用率定义扩展为「enact 后从未复核 + 从未触发保护性拒绝」的双零占比；申请频繁但从未被保护性拒绝的 enact 候选列入复核清单。

理由：复审正确指出 v0.3 的保护「只防删除、不防语义削弱」——而语义削弱（改弱安全表述、移到不敏感位置）恰是比删除更隐蔽的失效路径。只读化让保护语义完备；灵活性由授权通道保留，且授权本身留痕可审计。

四 / T1 v1.1

复现层级：T1 降格为「受控环境内可复现」（落实意见 4）

层级v0.4 定义声明措辞
T1 受控环境 七分量全部可记录且可钉死：权重快照、推理框架及版本、硬件型号、并行度与 batch 配置、浮点确定性设置、tokenizer 版本、上下文拼接模板版本 「在所记录环境内重放逐字节一致」；任一分量不可固定 → 自动归 T2，禁止手动标 T1
T2 别名+指纹同 v0.3（供应商别名 + 探针指纹 + 周期巡检）「条件复现：供应商版本未变时」
T3 仅别名同 v0.3「最佳努力复现，结论 14 天时效」

理由：权重固定不等于输出固定——GPU 非确定性算子、batch 变化、tokenizer 升级都会改变输出。把「环境」写进 T1 的定义，声明与能力严格对齐；自动降级规则堵住「标高层级」的诱惑。捕获清单相应扩容（新增框架/硬件/并行/浮点/tokenizer 五项），缓存键同步扩展。

五 / P0b Gates

P0b 改善门槛：意图分类取代单一回归门（落实意见 7）

复审指出：v0.3 的 P0b 出口只验「零回归」，一个从不改变行为的 no-op 补丁也能通过。直接补一道「必须改善」的门又会误伤合法的质量中性补丁（如纯删冗余）。解法是把「改善」定义在补丁自己声明的意图上：

意图典型场景成功判据（全部预注册）
improve补缺、加强约束、改写目标目标场景配对改善达最小效应（单侧 Wilcoxon p<α 且任务层中位配对差 ≥ δ_imp）＋父版本回归集非劣（TOST，ε_ni）
simplify删冗余、压缩、去未提及回归集非劣（TOST，ε_ni）＋渲染 token 下降 ≥ δ_cost（成本改善是它的目标，质量中性是它的约束）
fix修复失败签名指定失败签名在归因窗口内消除＋回归集非劣
protect登记保护类审计路径，无指标要求（ProtectionChange 通道）
无声明 / no-op无可测变化判失败，不得计入成功样本，不得作为策略学习正例
